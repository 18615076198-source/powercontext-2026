# 设计说明

## 1. 要解决的问题

规格驱动开发（SDD）里，Agent 每次动手前都要回答三个问题：

1. **该遵守哪些规格？** —— 规格散落在多个文档、还会随版本演进；
2. **该改哪些代码？** —— 同名函数很多，改错文件是最常见的失败；
3. **怎么证明没改坏？** —— 新behavior 要有功能用例，旧行为要有回归护栏。

`sddctx` 把这三件事变成一条可复现的流水线，并把每一步的产物落盘，形成证据链。

## 2. 数据流

```
                 ┌──────────────── seekdb（集合 sddctx_chunks）────────────────┐
 规格 md ─┐      │  spec:BR-REPORT-05   code:billing.report:build_monthly...   │
 源码 py ─┼─切分─▶│  test:tests.test_report:test_currency_filter               │
 测试 py ─┘      └───────────────▲──────────────────────────┬──────────────────┘
                                 │ upsert                   │ where_document $contains
                                 │                          ▼
   任务 JSON ──▶ 上下文包组装（锚点精确取 + 检索补充 + 来源校验）──▶ context-pack.json
                                 │
                                 ▼
                    提示词（规格 + 完整源文件 + 回归红线 + 输出协议）
                                 │
                            MiniMax M3.1-Flash（SSE 流式）
                                 ▼
                    整文件重写 ──护栏──▶ 落盘 + change.patch
                                 │
                                 ▼
                pytest：验收用例(功能) + tests/ 全量(回归) + 测试文件哈希
                                 │
                                 ▼
        PowerContext：memory(progress) + source(sdd-task-state) ──▶ 下个进程 context/prepare 召回
```

## 3. 关键设计决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 资料切分粒度 | 规格按 `## BR-*` 条目、代码按函数/类、测试按 `test_*` | 与「可追溯到条目编号」的验收方式对齐，行号可定位 |
| 检索方式 | seekdb `where_document` 全文下推 → 候选集 → 本地重排 | 小语料下全文下推足够快，且不依赖 embedding 模型下载；`SDDCTX_SEEKDB_EMBEDDING=default` 可叠加向量近邻 |
| 锚点机制 | 任务 JSON 声明 `anchors.spec_ids` / `anchors.symbols`，精确命中优先 | 保证「本次适用条目」不漏；检索只负责补充，不负责兜底关键项 |
| 模型输出协议 | 整文件重写（`=== FILE: ... ===`） | small-file 场景下比 unified diff 落地成功率高；diff 由本地生成，确定性更强 |
| 护栏 | 路径白名单 + 禁止改测试/规格 + `ast.parse` + 公共符号保留 | 把「模型能做什么」限制在可验证范围内，失败时拒绝落盘而不是带病写入 |
| 状态存储 | PowerContext Memory（紧凑 JSON）+ Source（完整证据） | Memory 保证可被 `context/prepare` 召回；Source 保留完整证据供人工审阅 |
| 兜底后端 | SQLite 实现同一 Store 接口 | Windows 无 `pylibseekdb`；两条后端共用同一批测试，行为一致性可验证 |

## 4. 失败模式与处理

| 失败模式 | 检测方式 | 处理 |
| --- | --- | --- |
| 规格还没写 | 锚点 `spec:BR-XXX` 查不到 | `plan` 输出 `gaps`，`apply` 拒绝执行并提示先做规格演进 |
| 资料导入后被人改过 | 整文件哈希比对 | `verify_sources` 报「导入后被修改」，`apply` 拒绝执行 |
| 模型改到测试/规格/越权路径 | 路径前缀 + `..` 检查 | 报错并要求模型重试一次，仍失败则一次都不写入 |
| 模型删掉既有公共函数 | AST 顶层定义集合比对 | 同上 |
| 模型输出语法错误 | `ast.parse` | 同上 |
| 测试被顺手改掉 | 回归用例文件哈希比对 | `verify` 输出 `tests_untouched=false` 并判定失败 |
| 连接被中间设备重置 | 非流式长连接静默超时 | 改用 SSE 流式接收，边收边读 |

## 5. 边界

- 面向中小型 Python 工程；跨语言需要补 `chunker`（当前 `tree-sitter` 未引入）。
- 只做单轮修改 + 单轮修复（`--max-attempts 2`），不做多轮自主迭代。
- 不做语义级等价性判断，"没改坏" 由回归用例定义。
