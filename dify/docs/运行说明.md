# 运行说明

## 1. 作品与体验方式

「赛博月老 · 缘分交易所」是一个 Dify Chatflow 应用：

- 用户在 Dify 对话界面（或 API）输入相亲简历 / 聊天内容；
- Dify 判断意图（查档案 / 撮合），调用配套后端的 HTTP 接口；
- 后端用本地 embedding 模型把简历向量化，在 **seekdb** 里做向量 + 全文混合检索，返回 3 位候选人；
- Dify 的 LLM 节点扮演月老生成撮合报告；
- 报告再写回 **seekdb** 的 `matches` collection，作为下一次（含新会话）的记忆。

## 2. 环境与版本

| 组件 | 版本 / 要求 | 说明 |
| --- | --- | --- |
| Dify | 1.x（DSL `version: 0.1.5`） | 社区版即可；建议 1.4+ |
| seekdb | 1.4.0 | MySQL 协议 `127.0.0.1:2881`，root/空密码 |
| Node.js | ≥ 20（实测 24.21） | 配套后端 |
| 模型服务 | 任意 OpenAI 兼容模型 | 在 Dify 里绑定到两个 LLM 节点；推荐 DeepSeek / Qwen / GPT-4o-mini |
| 后端 embedding | 内置 bge-small-zh INT8（22.9MB） | 不依赖外部 embedding API |

## 3. 启动步骤

### 3.1 seekdb

~~~bash
# 已有 seekdb：确认端口
mysql -h127.0.0.1 -P2881 -uroot -e "select 1"
# 没有则启动（数据目录自选）
seekdb --nodaemon --base-dir ~/seekdb-dify --port 2881
~~~

首次启动后端时，会自动创建数据库 `dify_matchmaker`、两个 collection 并写入 24 位角色，无需手工建表。

### 3.2 配套后端

~~~bash
cd dify
npm install
npm start
~~~

启动日志应包含：

~~~text
赛博月老后端已启动: http://0.0.0.0:7870
seekdb: 5.7.25-OceanBase seekdb-v1.4.0.0 | personas=24
~~~

自检：

~~~bash
curl http://127.0.0.1:7870/health
curl -X POST http://127.0.0.1:7870/api/match -H "content-type: text/plain" \
  --data-binary $'USER=demo\nPROFILE=程序员，喜欢猫和手冲咖啡\nMESSAGE=帮我撮合\nVIBE=认真'
~~~

### 3.3 导入 Dify DSL

1. 打开 Dify → 工作室 → 创建空白应用（或直接导入）：**导入 DSL 文件**，选择 `dsl/cyber-matchmaker.yml`；
2. 进入 Chatflow 画布，完成两处绑定（见 `dsl/README.md` 的截图说明）：

   | 位置 | 需要改什么 |
   | --- | --- |
   | 「月老撮合」「档案管理员」两个 LLM 节点 | 选择你环境里可用的模型（provider / model 均以你环境为准） |
   | 「seekdb 检索候选人」「读取相亲档案」「写入相亲档案」三个 HTTP 节点 | URL 里的 `http://host.docker.internal:7870` 改成后端地址 |

3. 右上角「发布」。

> 后端地址怎么填：
> - Dify 用 Docker Desktop（Windows/macOS）：保持 `http://host.docker.internal:7870`；
> - Dify 用 Linux Docker：在 compose 里给 api/worker 加
>   `extra_hosts: ["host.docker.internal:host-gateway"]`，或改为宿主机局域网 IP；
> - Dify 直接跑在宿主机：改成 `http://127.0.0.1:7870`。

### 3.4 体验

在 Dify 应用对话里：

1. 输入：「帮我撮合一下：程序员，28 岁，喜欢猫和手冲咖啡，周末想去看展」；
2. 输入：「再换一批」；
3. 输入：「查一下我的相亲档案」。

## 4. 数据初始化与重置

| 操作 | 命令 / 接口 | 说明 |
| --- | --- | --- |
| 重建角色池 | `POST /api/seed` 或 `node service/seed.mjs` | 删除并重建 `personas`，24 位角色 |
| 清空某人的档案 | 换一个 `sys.user_id`（新会话）即可 | 记忆按 user_id 隔离 |
| 清空全部档案 | 删除 `matches` collection（或重建数据库） | 演示前可做 |

角色数据在 `service/personas.json`，可自行增删；修改后调用 `/api/seed` 重建。

## 5. 网络与资源

- Dify 的 HTTP 节点必须能访问后端 `7870` 端口（容器 → 宿主）；
- 后端只需要 seekdb `2881` 与本地模型文件，不需要外网；
- 资源：后端常驻内存约 300–500MB（含 ONNX 模型）；24 位角色的索引刷新约 0.3–0.6s。

## 6. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| LLM 节点报「模型不可用」 | 导入后未绑定模型 | 在两个 LLM 节点里重新选择模型 |
| HTTP 节点 404 | URL 少了 `/api/match` 等路径 | 检查三个节点的 URL |
| HTTP 节点连接失败 | Dify 容器访问不到宿主 | 用 `host.docker.internal` 或宿主 IP，确认防火墙 |
| 候选人始终相同 | 用户是同一 `sys.user_id` 且历史为空 | 换会话/用户，或说「换一批」触发排除 |
| 报告里出现模板文字 | 本地执行器未接 LLM | 属预期；Dify 内由 LLM 节点生成 |
